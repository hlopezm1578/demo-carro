## Phase Goal (user story)

**As a** visitante de la tienda, **I want to** crear una cuenta, iniciar sesión con un token que
persiste entre recargas y armar un carro que sobrevive los full-page loads, **so that** llego al
checkout con mi identidad y mi compra listas cuando Webpay me devuelva a la tienda (fase 3).
Este plan entrega el contrato y los ADRs que hacen esa capability auditable (AUTH-01/02/03).

Purpose: D-15/ADR-007 ordenan contrato aprobado antes de codificar (aquí: antes de narrar código
en las guías). El tracer cablea el flujo registro → login → perfil → admin-estado de punta a
punta en la capa de mayor riesgo arquitectural (esquema de seguridad, schemas, códigos), y los
ADRs 009-011 registran las decisiones D-19..D-33 que las guías enseñan.

Output: contrato_api.yaml 0.2.0 extendido, ADRs 009/010/011 nuevos, README de 04_arquitectura
actualizado. TODO es documental (repo guide-only, D-17): nada se ejecuta.
